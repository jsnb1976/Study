## 2. Architecture Overview

Tardigradia 2.0 is a **2D HTML Canvas simulation** that replaces the existing floating-icon DOM approach with a full physics/ecology engine, while preserving the decorative bubbles, background, slideshow, and menu systems.

```
┌─────────────────────────────────────────────────────────────┐
│ index.html                                                  │
│  ├─ Background layer (existing: CSS background + bubbles)   │
│  ├─ Biome Canvas (new: full-screen 2D canvas, z-index 0)    │
│  ├─ HUD Overlay (new: semi-transparent panels, z-index 10)  │
│  └─ Existing DOM elements (sidebar, main-frame, nav-bar)    │
└─────────────────────────────────────────────────────────────┘
```

### Camera Model (2D Canvas with Translation/Rotation)
- **Normal mode**: camera at world origin, all creatures visible
- **POV mode** (first-person inside creature): canvas is translated so the tracked creature is at viewport center AND rotated to face the creature's current heading — creating the sensation of being "inside" the moving microbe. Zoom level increases (closer scale). Surrounding creatures pass by as the tracked creature propels forward.

### Physics Engine (2D)
- Delta-time driven `requestAnimationFrame` loop
- Each creature runs `update(dt, neighbors, resources, globalParams)`
- Per-species movement behaviors adapted from TGPU particle physics
- Reynolds flocking for swarm species
- Curl-noise flow field for fluid substrate background motion

```
[PRODUCERS]            Bacteria spp. — regenerate from nutrients
```

### Auto-Balance Logic (Lotka-Volterra influenced)
- Each species has a `targetRatio` (fraction of total population)
- If a species drops > 30% below its target: spawn bonus (free energy injection)
- If a species exceeds 200% of target: predation pressure increases
- Global carrying capacity is set by the Resolution parameter

## 6. Feature Specifications

### CORE: Biome Simulation Engine (`biome_engine.js`)

- Full-screen `<canvas id="biome-canvas">` appended to `<body>`, positioned absolute, z-index 0 (above CSS background, below DOM UI elements)
- World space: 3000×2000 virtual units; maps to viewport via camera transform
- `requestAnimationFrame` loop, delta-time capped at 50ms
- Renders:
  1. Animated fluid flow field (curl noise, faint directional lines/particles)
  2. Creature sprites (drawImage of `_icon.png` files, scaled by creature size)
  3. Trail layer (fading canvas overlay, toggled)
  4. Selected creature highlight ring
  5. Interaction sparks (eat/reproduce events)
- Global params object (`biomeParams`) shared by all modules:
  - `speed`, `density`, `coherence`, `trailsOn`, `resourceRegen`, `energyRate`
  - `randomToggle_[paramName]` booleans for feature G

### Feature A: UI Slide-Away Menus

- **Right sidebar**: inherit existing `menu.js` pattern, upgrade to slide completely off-screen (translateX to `calc(100% + 5px)`) with smooth CSS transition; a thin `◀` pull-tab remains visible at all times
- **HUD panels** (top status bar, left ecosystem info, right controls): each panel has an independent collapse button; panels slide out to their respective edges
- **Title "Tardigradia land o lil"** stays fixed; all other text is in panels that can be hidden
- A master `☰ Hide All` button collapses every panel simultaneously (same as TGPU's "Hide Panels" button)

### Feature B: First-Person POV Inside Creature

- Any creature can be selected by click/tap on its icon in normal view
- On selection, a smooth transition (300ms ease) zooms the canvas in and translates to center on the creature
- **Camera transform** each frame:
  ```javascript
  ctx.translate(viewport.cx, viewport.cy);
  ctx.rotate(-creature.heading);      // rotate canvas opposite to creature's direction
  ctx.translate(-creature.x, -creature.y); // center on creature
  ctx.scale(POV_ZOOM_FACTOR, POV_ZOOM_FACTOR); // zoom in ~3×
  ```
- The tracked creature renders as a slightly pulsing, illuminated icon in the centre
- Surrounding creatures move past as the tracked creature propels forward
- Top HUD overlay shows: species name, energy bar, age, particle analogue name
- Press `ESC` or click the creature again to exit POV mode
- All POV state is managed by `pov_camera.js`

### Feature C: Anti-Screensaver

`screensaver.js`:
1. Requests Screen Wake Lock API (`navigator.wakeLock.request('screen')`) on activation
2. Re-acquires lock on `visibilitychange` (tab refocus)
3. Fallback: if Wake Lock not available, simulates minor pointer movement every 30s (synthetic `mousemove` event — keeps most OS screensavers at bay)
4. Toggle button in HUD: `☀ Screen Awake ON/OFF` with status indicator

### Feature D: Species Population Controls

- Each species (or phylum group) has a dedicated `<input type="range">` slider in the Controls HUD panel
- Range: 0–200% of target population
- Slider value maps to a `manualMultiplier` per species stored in `biomeParams`
- Biome engine uses `manualMultiplier` when calculating auto-balance target
- A `+ Add` / `- Remove` button pair also available for quick ±5 spawns

### Feature E: Save / Load Progress

`save_load.js`:
- **Save**: Serializes the full `biomeState` to JSON:
  - All creature positions, velocities, energy, age, species
  - Current `biomeParams` (speed, density, all sliders)
  - Camera state
  - Ecosystem resource levels
  - Timestamp
  - Saves to `localStorage` key `tardigradia_v2_save`
- **Load**: Deserializes, spawns creatures from saved positions, restores params
- UI: `💾 Save` and `📂 Load` buttons in HUD, confirmation toast notification
- Autosave every 5 minutes to a separate `tardigradia_v2_autosave` key
- Visual confirmation: brief green flash on canvas border on save

### Feature G: Random Manipulation Toggles

Each slider/control has an adjacent `🎲` toggle button. When enabled:
- A `RandomController` service (inside `hud.js`) applies a slow sinusoidal oscillation to that parameter over time, with configurable amplitude and period
- Oscillation uses `sin(time * freq + phase)` with per-parameter randomized `freq` (0.05–0.3 Hz) and `phase`
- Visual indicator: the slider thumb glows when random mode is active
- Parameters with random mode available:
  - Larmor Frequency, Population per species, Fluid Viscosity, Resource Regen, Energy Rate, Flock Cohesion

A master `🎲 Randomize All` toggle governs all at once.

### Feature H: Universal Resolution Setting

Available both in the Opening Screen AND accessible mid-simulation from the HUD:
- **Low**: maxCreatures=120, no trails, no glow, simple drawImage
- **Medium**: maxCreatures=380, 40-frame trails, subtle glow (canvas shadow)
- **High**: maxCreatures=750, 120-frame trails, full glow, anti-alias
- Changing mid-simulation culls/adds creatures proportionally; trails are cleared

## 7. Technical Implementation Notes

### Canvas Rendering Strategy
- Two canvases layered:
  1. `trail-canvas` — persistent layer; each frame draws semi-transparent black rect to fade trails
  2. `biome-canvas` — cleared each frame; renders all current creature positions
- `trail-canvas` opacity `0.92` (slow fade at 60fps); `0.80` at high quality
- Creature sprites: preload all `_icon.png` images into `Image` objects at startup; cache in a `Map<speciesKey, HTMLImageElement>`

### Creature Class (`creature.js`)
```javascript
class Creature {
  constructor(species, x, y)
  update(dt, neighbors, biomeParams, resources)
  draw(ctx)
  applyFlocking(neighbors, params)
  applyParticlePhysics(dt, params) // species-specific from TGPU mapping
  eat(other) → returns energy gained
  reproduce() → returns new Creature | null
  die() → marks for removal, releases nutrients
}
```

### Physics Module (`physics.js`)
Key functions:
- `flockingForce(creature, neighbors, cohesion, separation, alignment)` — Reynolds rules
- `curlNoise(x, y, t)` — returns `{vx, vy}` flow field vector
- `cliffordAttractor(x, y, a, b, t)` → for electron-type creatures
- `bec_cluster(creature, peers, t)` → for axion-type clustering
- `acoustic_wave(x, y, origin, t)` → for Pines Demon pheromone wave

### Ecosystem Module (`ecosystem.js`)
- `ResourceGrid`: 2D grid (50×33 cells) of nutrient values, regenerated over time
- `interactionCheck(creatureA, creatureB)` → determines if eating/competing/ignoring
- `autoBalance(creatures, params)` → calls spawn/cull helpers each 5s to maintain target ratios

## 11. Design Decisions & Assumptions

| Decision | Rationale |
|---|---|
| 2D Canvas (not Three.js) | Preserves microscope-slide aesthetic; lower GPU cost; simpler POV transform |
| First-person POV via canvas rotation+translation | Matches user's requested "inside creature" style; canvas transform sufficient for 2D |
| Icon PNGs reused from existing data | All `_icon.png` files already exist at creature image paths |
| Opening screen replaces immediate launch | Gives user control per Feature F; defaulted to sensible values |
| Trail canvas as separate element | Avoids re-rendering background every frame; enables independent trail control |
| localStorage for save (not file export) | Simpler UX; no server needed; user can export JSON via console if wanted |
| Wake Lock API primary screensaver | Modern browsers support it; `mousemove` synthetic event as graceful fallback |
| Species grouped into 6 trophic-role buckets | 33+ individual species is unwieldy for opening screen sliders; groups are biologically meaningful |
| Subatomic controls mapped bi-directionally | Changes in HUD sliders affect both the physics engine and the TGPU-inspired metrics chart |
